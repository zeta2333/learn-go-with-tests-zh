# 04 — 审校诊断（只诊断，不改文）

对照 source.md 逐段审 03-draft.md，诊断如下。

## A. 准确性

1. **"比分"用词不当**（初译"先不考虑真正的比分和 JSON"）：原文 actual scores 指玩家得分（胜场数），"比分"易被理解为双方对赛比分。应作"得分"。
2. **"让编译器闭嘴"语气偏离**："get the compiler happy for now" 是"暂时让编译器满意"，"闭嘴"过狠且带有原文没有的情绪，宜作"先哄得编译器开心/满意"。
3. **错字/残留**：`*以后*我们是要给这段代码写测试 的。` —— "测试"后多一个空格；且句式生硬，原文 "we're going to want to test this" 是"以后会想给这段补测试"，可译得更顺。
4. **"借用一个实现的部分片段"拗口**："borrow pieces of an implementation" 直译痕迹重，宜作"借用一部分现成的实现"。
5. **"组合出新接口"主语丢失**：原文 "You can use it with interfaces to compose new interfaces" 强调"你可以把它用在接口上"，初译"接口可以嵌入接口"丢了这个视角，但也更顺口；折中为"把接口嵌进接口，就能组合出新接口"。

## B. 中文表达

6. "现搭一个路由器然后再调用它" 通顺，保留。
7. "测试各归各位""可爱的对称"等口语化表达符合全书文风，保留。
8. "先造点孽"（commit some sins）幽默保住了，保留。
9. "`/league` 端点也有了个开头"（have the start of）可再自然一点："算是搭好了架子"或保留"有了个开头"，取后者（更贴原文的未完成感）。
10. "忍着……那股别扭劲儿" 生动的口语，保留。

## C. 加注与体例

11. 首现括注检查：league table（联盟积分表）、embedding（嵌入）、ServeMux（请求多路复用器）、Decoder（解码器）、Encoder（编码器）、stub（预置）均已首现加注，无重复加注。
12. spy、fake 按词汇表保持英文、不加注，与 mocking 章一致。
13. 弯引号体例合规；无直角引号；行内代码均入反引号。
14. "上一章（英文原版）"链接处理符合未译章节规范。

## 结论

问题集中在 A1–A5 五处，均为局部词句修订，不涉及结构。
