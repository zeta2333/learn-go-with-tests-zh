# 00 — 全书共享翻译规范（learn-go-with-tests 中译）

每一章的翻译都遵循本规范 + 用户级术语表 `~/.config/baoyu-skills/baoyu-translate/EXTEND.md`（40+ 条，持续回填）。
样章 hello-world 的定稿 `_translation/hello-world/translation.md` 是文风的基准参照。

## 风格

- **conversational**：像有经验的同事面对面带你入门；原作者的幽默（自嘲、夸张、英式感叹）必须保住，不译平。
- 读者是**开发者**：终端、编辑器、HTTP 等常识不解释；Go 特有概念（包、模块、接口、切片、具名返回值……）首现时用「中文（English）」或加粗括注轻量点一次。
- 忌翻译腔：长定语链、名词堆砌、"被"字滥用、"因此/然而/此外"连词堆叠。多用短句和自然的祈使句。
- 中英混排：中文与英文单词/代码之间加空格；代码标识符一律反引号。

## 硬性规则

1. **代码块、终端输出、错误信息与原文逐字节一致**，两个例外（都是功能性注释，保留英文）：① Go 代码块里的 `//` 注释随章翻译；② Example 函数的 `// Output:` 注释**不译**（`go test` 据此校验示例输出，动了会失效）。字符串字面量、输出样例、路径、原文即有的笔误都不改。
2. **跨章内部链接**：链接目标页保持上游同名文件（如 `hello-world.md`），锚点改写成中文标题对应的 slug（标题去掉标点、空格变 `-`，如 `#最后一次重构`）。**前向引用尚未翻译的章节时**，改为指向该章的上游 GitHub 文件 URL 并在链接文字处注明"（英文原版）"，译出后换回。
2. 行内代码、加粗、斜体、图片、链接、标题层级与原文一一对应；所有外链 URL 原样保留。
3. **清除上游为 Gitbook 加的转义符**：正文里的 `\.` `\/` `\(` `\)` `\_` `\!` `\[` 等去掉反斜杠按正常文本写（mkdocs 不需要它们）。反引号内的内容不动（如 `%USERPROFILE%\go\bin`）。
4. 直角引号「」一律不用，统一弯引号""；代码字面量进反引号。
5. 章节标题意译为自然中文；专有名词式标题（如 `Select`、`switch`、`Context`）可保留英文。
6. 段落顺序、教学步骤的因果链与原文严格对应，不合并、不拆移。
7. 术语首现加注一次即可，全书只注一次由主控在终审时统一，译者按"首现加注"处理。
8. 章首"本章所有代码"链接保留指向 quii 原仓库对应目录。

## 流程（每章）

1. 复制原文到 `_translation/<章>/source.md`
2. `01-analysis.md`：内容概述、本章新术语、翻译难点（简明，几十行内）
3. `02-prompt.md`：本章特有约束（新术语定名、幽默点对策）
4. `03-draft.md` 初译 → `04-critique.md` 对照原文审校（准确性/中文表达/加注是否得当，只诊断）
5. `05-revision.md` 按诊断修订 → 通读润色成 `translation.md`
6. 运行 `python3 _translation/verify.py _translation/<章>/source.md _translation/<章>/translation.md`，失败则修复后重跑直到 OK
7. 报告：新术语（英→中定名）、发现的图片引用、原文疑似笔误

## 图片章节
