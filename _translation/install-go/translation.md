# 安装 Go

Go 的官方安装指南可以在[这里](https://golang.org/doc/install)找到。

## Go 环境

### Go 模块

Go 1.11 引入了[模块（Modules）](https://go.dev/wiki/Modules)。从 Go 1.16 起，这种方式已成为默认的构建模式，因此不再推荐使用 `GOPATH`。

Modules 的目标是解决依赖管理、版本选择和可重现构建这几类问题；它也让用户可以在 `GOPATH` 之外运行 Go 代码。

**先补一点背景：Modules 出现之前是什么样的。** 在 Go 1.11 之前，Go 工具链依赖一个叫 `GOPATH` 的约定：一个环境变量，指向你机器上的某个单一目录（通常是 `~/go`），所有 Go 代码都必须放在那里。每一个项目、每一个依赖、每一个编译好的包，全都存在那个目录下面。这就意味着，你不能随手在电脑上建个文件夹就开始写 Go 代码；离开 `GOPATH`，编译器不知道该如何解析 `import`。

**Modules 是如何逐一解决这些问题的。** 依赖管理方面，项目里的 `go.mod` 文件会显式声明你的代码需要哪些外部包、需要什么版本，跟 Node.js 里的 `package.json` 类似。版本选择方面，Go 使用一个叫最小版本选择（Minimum Version Selection，MVS）的确定性算法：当多个依赖对同一个包要求的版本各不相同时，Go 总是选出能满足所有方的最低版本，结果因此可以预测。可重现构建方面，Go 会在 `go.mod` 旁边生成一个 `go.sum` 文件，里面记录每个依赖的加密哈希值。任何人构建这个项目，下载到的都会是完全相同的文件，并依据这些哈希逐一校验；远端服务器上只要有任何变动，构建会立刻失败。

**为什么 Modules 允许代码放在 `GOPATH` 之外。** 当 Go 在某个目录里发现 `go.mod` 文件，这个文件就成了项目的锚点。工具链以它为准，把所有 `import` 都解析到这个模块之下，不再需要全局的 `GOPATH` 引用。这意味着你可以在机器上的任何地方创建项目文件夹，编译器都认得。

用起 Modules 来相当简单。随便选一个 `GOPATH` 之外的目录作为项目根目录，然后用 `go mod init` 命令创建一个新模块。

这样就会生成一个 `go.mod` 文件，内容包括模块路径、Go 版本，以及依赖要求——也就是构建成功所需要的其他模块。

如果不指定 `<modulepath>`，`go mod init` 会根据目录结构猜一个模块路径；也可以通过传入参数来覆盖它。

```sh
mkdir my-project
cd my-project
go mod init <modulepath>
```

一个 `go.mod` 文件大概长这样：

```
module cmd

go 1.24

```

这里声明的 Go 版本可不只是个摆设：就算你装的是更新的 Go，工具链也会用它来决定适用哪套语言语义。举个例子，Go 1.22 改变了 `for` 循环变量的行为，所以依赖这一行为的代码（比如后面[并发](concurrency.md)一章里我们就会用到）需要 `go.mod` 里声明 `1.22` 或更高版本，才能按预期工作。让这个版本号别太落伍，能帮你省掉日后一些莫名其妙的调试。

内置文档提供了所有可用 `go mod` 命令的总览。

```sh
go help mod
go help mod init
```

## Go 代码检查

可以用 [GolangCI-Lint](https://golangci-lint.run) 配置出比默认 linter（代码静态检查工具）更好的代码检查方案。

安装方式如下：

```sh
brew install golangci-lint
```

## 重构与你的工具

本书的一大重点，就是重构的重要性。

顺手的工具能让你更有底气地做大范围的重构。

你应该把编辑器用熟，做到用一组简单的组合键就能完成下面这些操作：

- **提取/内联变量**。把魔法值抓出来给它们起个名字，能让你快速简化代码。
- **提取方法/函数**。能把一段代码抽出来变成函数/方法，这一点至关重要
- **重命名**。你应该能放心大胆地跨文件重命名符号。
- **go fmt**。Go 自带一个颇有主见的格式化工具，叫 `go fmt`。你的编辑器应该在每次保存文件时都跑一遍。
- **运行测试**。做完上面任何一项操作之后，你应该能马上重新运行测试，确认重构没有弄坏任何东西。

另外，为了帮你更好地跟代码打交道，你还应该能做到：

- **查看函数签名**。在 Go 里，你永远不该对"怎么调用一个函数"心里没底。你的 IDE 应该为你展示函数的文档、参数和返回值。
- **查看函数定义**。要是仍然不清楚某个函数是干什么的，你应该能跳到源码里，自己想办法弄明白。
- **查找符号的引用**。了解一个函数的使用场景，能帮你在重构时做出决策。

把工具用熟，你才能把注意力集中在代码上，减少上下文切换。
