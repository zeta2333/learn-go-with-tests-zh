# 04 — 审校诊断（对照原文，只诊断不改稿）

## 准确性

1. 开篇段"脚下垫着几个 G 的转译 JavaScript，手里还得伺候一套拜占庭式的构建系统"：原文 built upon / working with 两个分词结构，译文比喻杂糅（"垫在脚下"与"伺候"打架）。
2. "在我看来"段第二句："没有索引页，我们也照样能发布产品"——原文只是 "We could launch this product and share direct links"，无"没有索引页也行"的让步含义，属增译走样。
3. 引文（html/template 包文档）"可防御代码注入"搭配生硬，应为"能抵御/防住代码注入"。
4. "相当可以忽略"（基准测试段）不成话；原文 fairly negligible / pretty negligible 两处，需分开译且自然。
5. "模板会把 `{{.Description}}` 这类占位替换成……"：术语表定名是"占位符"，漏"符"字。
6. "你测这段逻辑的唯一手段就是渲染 HTML 然后比较字符串"——accurate；"*_重要的_*"等三处 `*_…_*` 斜体写法不规范，统一 `*…*`（模板周围、视图、轻微、重要的）。
7. "她提到的'组合测试'"——原文 "Combinatorial Testing" is definitely something worth looking into，"她提到的"为增译，删。
8. "两个文件，如果对改动满意"前句"Give them a look"已译"看看这两个文件"，准确。

## 中文表达

9. "我们还希望全站观感一致……比如 `<html>`、还有装着 CSS 样式表链接和我们想要的其他东西的 `<head>`"——定语过长，拆开。
10. "尽管如此，先忍一忍，*暂时*受着这份痛"——"忍一忍"与"受着"语义重复。
11. "写这个东西*感觉很*别扭"——斜体应落在"感觉"上。
12. "它看着像 HTML，却没法像"正常"的 HTML 文件那样去编辑它"——"它……它"重复；"我们想做的是让模板住进单独的文件里：这样能更好地组织它们，也能像对待 HTML 文件一样对待它们"——"对待"重复。
13. "可一旦这么做……可说实话……"相邻两段都以"可"开头，第二处改"但说真的"。
14. "工作成本也会螺旋失控"→"失控地螺旋上升"。
15. "这套做法让管理 HTML 这种又大又丑的东西的改动简单得多"——"让管理……的改动"嵌套过深。
16. "这其实只是审批测试一个相当小的用法"——语序，改"审批测试相当小的一个用法"。
17. "有了这次改动，代码测试充分的好处我们照单全收"——"照单全收"与原意（still benefit from）不合。
18. "把它拷贝覆盖旧版本，即为批准"——"即为"书面腔，改"就算批准了"。
19. "索引页表面上看起来简单"——"表面"与"看起来"重复。
20. "相当可以忽略"（见 4）；"它们仍然比你会写的大多数单元测试更昂贵"→"维护成本更高"；"我们仍然要努力架构代码"→"努力设计代码结构/架构好代码"。
21. "并且装成模板语言用起来方便的样子"→"按模板语言用起来顺手的方式组织"。
22. "又不能直接遍历 `[]Post` 在内存里做替换"——"又"字承接不明，改"不能图省事直接……"。
23. "到了这一步，我还不怎么在乎具体标记长什么样"——"到了这一步"歧义（像指步骤），实指设计阶段。
