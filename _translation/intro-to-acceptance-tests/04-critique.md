# 04 审校诊断（对照 03-draft.md，只诊断不改动）

## A. 准确性 / 规则硬伤（必须修）

1. **漏链接（verify 会挂）**：Wrapping up 段 "a headless web browser like [Selenium](https://www.selenium.dev/)" —— 草稿只写了文字没带链接。
2. **行内代码缺失**：CanGet 讲解段 "fire off a `GET` to `URL`" —— 原文 `URL` 带反引号，草稿写成了裸 URL。
3. **"By their nature" 误译**：草稿作"顾名思义"（as the name implies），原义是"就其本质而言"，语义偏差。
4. **术语不一致**：in-flight 一词两译——前文"还在处理中的 HTTP 请求"，后文列表"让在途的请求跑完"。统一为"在途请求"，首现括注英文。
5. **文档引文语义**："等待各条连接回到空闲状态并将其关闭"有歧义（关闭的是服务器而非连接）：原义 wait for connections to return to idle, then shut down（服务器关停）。
6. **招聘段语义走样**："一个大家伙一起解决有趣问题的环境"——原文是 "an environment with other engineers solving interesting problems"（和其他工程师一起），"大家伙"完全跑偏。

## B. 中文表达（应修）

7. **"去行使系统"生硬**（两处）：exercise the system 应为"使用/操作这个系统"，"行使"配"权利"不配"系统"。
8. **"这是一个优点，因为这意味着……这意味着"**：同词连用重复，后一个可省。
9. **"本章会以 HTTP 服务器为语境"**："为语境"翻译腔 → "结合 HTTP 服务器这个场景"。
10. **"取决于你软件的性质"** → "视你软件的性质而定"更顺。
11. **"庆幸的是"** → "好在"更口语、更贴作者语气。
12. **"它无聊、无法规模化、不准确，而且浪费"**："而且浪费"悬空 → "而且纯属浪费"。
13. **"你可以在这里到 GitHub 上查看"**：语病，"这里"与"到"冲突 → "可以到 GitHub 上查看"。
14. **"验收测试的高层次步骤"**："高层次"翻译腔 → "高层步骤"或"整体步骤"。
15. **"再强调一次很重要的一点"** → "值得再强调一次"。
16. **"这会在我们的事故告警频道里触发一条告警"**："告警"相犯 → 频道名去"告警"，作"事故频道"。
17. **"住在伦敦或波尔图附近或周边"**："附近或周边"叠床架屋 → "住在伦敦或波尔图一带"。
18. **首段三个"如何"排比略啰嗦**：合并为"……分享包，减少维护投入，并对自己工作的质量更有信心"。
19. **"既全面、又能描述行为"** 顿号+又结构别扭 → "既覆盖全面，又描述了行为"。
20. **lead time 加注重复**：缺点列表（首现）已括注（lead time），紧随其后的标题《前置时间（lead time）？》再去一次英文显得重复 → 标题简化为《前置时间？》。
21. **可测试示例**：术语表定名"可测试示例"，首现宜括注英文（Testable Examples）。

## C. 风格 / 体例（可选）

22. "到时候你就熄灯走人了"：保住了 lights out 的幽默，保留。
23. "本章把验收测试装进了你的测试工具箱"：原文自称 blog post，此处按书章语境译作"本章"，体例统一，已在 02-prompt 记录。
24. 代码块两处上游笔误（`"<http://localhost:"`、`"cannot run temp converter"`）逐字节保留，报告备案。
