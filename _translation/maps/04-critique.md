# maps 章 — 审校诊断（对照原文，只诊断不改稿）

## A. 准确性

1. **开篇 `key` 未译**：首段"按 `key` 存放条目"保留了反引号英文，与本章规范（key→键、value→值）冲突，且与第二段"键（key）"重复加注。→ 统一：首段写"键（key）"，第二段直接用"键/值"，不再二次加注。
2. **word 译名不统一**：第二段"把键想成词条"，后文均用"单词"。→ 统一为"单词"。
3. **Dave Cheney 引文未译**：`> A map value is a pointer to a runtime.hmap structure.` 原样保留英文。引文可保留原句，但必须补中文译文，否则读者断片。→ 保留英文原句 + 括注意译。
4. **web 应用 blockquote 未译**：`> You can redirect the user...` 是作者自拟示例，不是外文引文，保留英文不妥。→ 整句译成中文。
5. **"magic error" 译成"错误字符串"**：原文 "get rid of the magic error...extracting it into a variable"，抽的是 error 值不是字符串；"代码就清爽了"为添加成分。→ 改"写死的错误"，删添加语。
6. **`hash map` 行内代码被化掉**：原文 "an empty `hash map`" 是反引号行内代码，译文改成"哈希表（hash map）"丢了体例。→ 恢复 `hash map` 反引号，括注可保留在代码外。
7. **nil map 初始化表述**："永远不要把 map 变量搞成下面这样的 nil 零值"——原文 "you should never initialize a nil map variable" 语义是"别把变量初始化成 nil（留在零值态）"，"搞成"过于口语且因果略歪。→ "千万不要像下面这样把 map 变量留在 nil 零值态"。
8. **总结两条不达**："如何创建作为常量的错误"生硬 → "如何创建常量形式的错误"；"编写错误包装"易与 Go error wrapping（%w）混淆 → "编写错误包装类型"。
9. **"except we switched..." 双关丢失**：switch 语句 / 位置对调一语双关，译文只留了对调义。→ 译文里保留 `switch` 字样呼应："只是 `switch` 里干的活正好对调了"。

## B. 中文表达

10. **"（……它可能恰恰是关键所在。）"**：key 双关（键/关键）被磨平。作者原话 "could be key" 是轻巧的俏皮话。→ 译作"它可能恰恰是 key——关键所在"，前文已注"键（key）"，读者能会意，不加译者注不打断。
11. **"含有一个单词的 `Dictionary`"**：量词堆叠生硬 → "带有一个单词的 `Dictionary`"。
12. **"我们借助 `Search` 函数来验证词典，能省一点事"**：语序别扭 → "我们借助 `Search` 函数来做验证，让这件事省力一点"。
13. **"现在我们又得到两个失败："**：可再顺一点 → "现在我们又多了两个失败"。
14. **"修 `Add` 的问题时我们已经见过怎么做了。那就来实现一个跟 `Add` 非常相似的东西吧。"**：两个"Add"连用略拗 → 前半改"这个问题我们在修 `Add` 时已经见过解法了"。
15. **"Our `Add` is looking good. Except, ..."**：译文"只是——我们还没考虑过……"破折号可留，语气 OK，保留。
